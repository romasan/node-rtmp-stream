# Анализ журнала пикселей

[analyzePixels.js](./analyzePixels.js) читает журнал игры и выводит JSON с признаками автоматизации и координации между аккаунтами.

## Запуск

Из корня репозитория:

```bash
node tools/analyzePixels.js > /tmp/pixel-report.json
```

По умолчанию читается `db/pixels.log`. Для другого журнала передайте путь первым аргументом.

```bash
node tools/analyzePixels.js db/pixels.log > /tmp/pixel-report.json
```

Каждая строка журнала имеет формат `timestamp;service;x;y;color;uuid;ip;nickname`. Время указано в миллисекундах Unix, координаты могут быть отрицательными. Некорректные строки пропускаются и учитываются в `summary.invalidLines`. Если записи идут вне хронологического порядка, скрипт сортирует события по времени перед анализом. В примерах из отчёта поле `line` содержит номер строки исходного файла, начиная с 1.

## HTML-отчёт

Преобразуйте готовый JSON в один HTML-файл с помощью [renderPixelReport.js](./renderPixelReport.js).

```bash
node tools/renderPixelReport.js /tmp/pixel-report.json > /tmp/pixel-report.html
```

Откройте HTML в браузере. В нём можно раскрыть группы синхронности, перейти к связанным линиям и посмотреть координаты, время по Москве и номера строк лога. Файл работает без подключения к сети и содержит IP-адреса из исходного отчёта.

## Признаки по отдельным аккаунтам

Массив `accounts` содержит UUID, у которых сработал хотя бы один из признаков. Если UUID встречался под разными никами, отчёт показывает все зафиксированные варианты.

| Признак | Условие |
| --- | --- |
| `rapid` | Не менее пяти интервалов короче одной секунды между последовательными пикселями аккаунта. |
| `regular` | Среди интервалов до 10 минут включительно есть хотя бы десять. Не менее 80% из них близки к медиане. Допуск равен большему из 100 мс и 5% медианы. |
| `straight_run` | Не менее 20 последовательных пикселей с одинаковым шагом в одну клетку по прямой или диагонали. |
| `raster_scan` | Не менее трёх соседних горизонтальных рядов с одинаковыми границами и шириной от восьми пикселей. Ряды могут заполняться в одном направлении или змейкой. |

Для `straight_run` и `raster_scan` разрыв между пикселями не превышает 10 секунд. В поле `spatial` сохраняется самый длинный найденный эпизод каждого вида. `sharedIps` перечисляет IP, с которых ставили пиксели как минимум два UUID. Общий IP может указывать на общую сеть или прокси.

## Совместные линии

В `coordinatedPaths` попадают линии из соседних пикселей одного цвета. Скрипт ищет их в восьми направлениях и связывает каждый пиксель с последним подходящим пикселем на предыдущей клетке, если между ними прошло не больше пяти секунд. События в других частях холста не прерывают линию.

Эпизод должен содержать не менее 20 пикселей. UUID должен меняться хотя бы на половине переходов, а минимум два аккаунта должны поставить по три пикселя или больше. У эпизода есть границы, цвет, вклад каждого UUID и список `placements` в порядке установки.

## Граф синхронности

[Модуль графа](./pixelSynchronization.js) считает совпадения между парами UUID. Пара пикселей подходит, если цвета совпадают и разница по каждой оси не больше двух клеток. Быстрые совпадения (`matches`) имеют задержку до 1,5 секунды включительно. Для сравнения скрипт считает совпадения в таком же по длительности диапазоне от 8,5 до 10 секунд (`controlMatches`).

В `synchronization.edges` попадают пары с 20 быстрыми совпадениями или больше, распределёнными как минимум по трём минутным окнам. Дополнительно требуется `lift` не ниже 3, где `lift = (matches + 1) / (controlMatches + 1)`. Один пиксель может входить в несколько совпадений. В `examples` можно посмотреть задержки, координаты и номера строк лога.

`synchronization.clusters` объединяет UUID в связные компоненты. Связи A–B и B–C дают одну группу, даже если связи A–C нет. Поле `density` показывает долю существующих связей от всех возможных внутри группы.

- `synchrony` — группа выделена по графу.
- `synchrony_and_shared_path` — как минимум два участника группы также встречаются в одном эпизоде совместной линии. `relatedPathIndexes` содержит индексы этих эпизодов в `coordinatedPaths`, начиная с 0.

Совместные линии и граф анализируются по UUID независимо от IP. События с сервисом `local` исключаются из обоих групповых методов.

## Как читать результат

Для проверки группы откройте её связи в `synchronization.edges`, затем сверяйте `examples` и связанные эпизоды с исходным логом. Пороги анализа записаны в `thresholds` и `synchronization.thresholds`.

Отчёт размечает наблюдаемые паттерны. Схожий результат может дать команда, которая вручную рисует по общему шаблону, поэтому вывод об автоматизации требует проверки контекста.
