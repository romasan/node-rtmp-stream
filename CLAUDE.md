# Инструкции для Cline

## Обязательное правило: синхронизация с README.md

**Этот файл содержит обязательные инструкции. Cline ДОЛЖЕН следовать им при выполнении ЛЮБЫХ задач в этом проекте.**

### 1. Проверка соответствия документации

Перед завершением любой задачи, связанной с изменениями кода, конфигурации, скриптов или структуры проекта:

1. **Прочитай актуальную версию `README.md`** — особенно разделы, относящиеся к затронутой области.
2. **Проверь, не противоречат ли внесённые изменения** тому, что написано в `README.md`:
   - Новые/удалённые файлы или директории → проверь раздел «Структура проекта»;
   - Изменение стеков, зависимостей, версий → проверь раздел «Стек технологий»;
   - Изменение эндпоинтов API, протоколов, форматов данных → проверь раздел «Как это работает» и таблицы эндпоинтов;
   - Новые/изменённые ключи конфигурации → проверь раздел «Конфигурация (`server/config.json`)»;
   - Новые/изменённые npm-скрипты → проверь раздел «Основные скрипты (`package.json`)»;
   - Изменение CI/CD → проверь раздел «CI/CD»;
   - Изменение способов авторизации, БД, хранения → проверь соответствующие разделы;
   - Добавление/удаление страниц, разделов приложения → проверь «Структура проекта» и «Как это работает».

### 2. Обновление документации

Если изменения **противоречат** существующему `README.md` ИЛИ добавляют новую функциональность:

1. **Обнови `README.md`** в рамках той же задачи (не откладывай на потом).
2. Изменения должны быть **точными и актуальными** — не добавляй вымышленных деталей, описывай только то, что реально реализовано.
3. Соблюдай **существующий стиль** `README.md`:
   - Заголовки: `#` для названия проекта, `##` для разделов, `###` для подразделов;
   - Разделители `---` между крупными секциями;
   - Таблицы в Markdown-формате;
   - Код и пути — в обратных кавычках;
   - Язык — русский.
4. **Новые фичи** добавляй в соответствующий раздел «Как это работает» (новый подраздел `### N. Название`) и/или в «Структура проекта», «Конфигурация», «Основные скрипты» — в зависимости от того, что изменилось.
5. Если фича затрагивает несколько разделов — обнови их все.

### 3. Чего НЕ делать

- **НЕ игнорируй** `README.md` при внесении изменений.
- **НЕ удаляй** и **НЕ переписывай** существующие разделы `README.md` без необходимости — только точечно обновляй затронутые места.
- **НЕ добавляй** в `README.md` информацию, которая не соответствует реальному состоянию проекта.
- **НЕ оставляй** документацию в состоянии, противоречащем коду, даже если задача казалась «мелкой».

### 4. Проверка перед завершением задачи

Финальный чек-лист перед `attempt_completion`:

- [ ] Изменения внесены в код/конфигурацию/структуру проекта.
- [ ] `README.md` прочитан и проверен на соответствие.
- [ ] Все противоречия в `README.md` устранены.
- [ ] Все новые фичи описаны в `README.md`.
- [ ] Стиль `README.md` соблюдён (структура, таблицы, язык).

## Обязательное правило: ведение CHANGELOG.md

При внесении **любых** изменений (новые фичи, исправления, изменения поведения) добавляй запись в `CHANGELOG.md`:

1. Запись добавляется в начало списка под заголовком с текущей датой (формат `DD.MM.YYYY`). Если запись за сегодня уже существует — добавь новый пункт в неё.
2. Язык записей — **английский** (в отличие от `README.md`, который ведётся на русском).
3. Описание — одно короткое предложение (не больше 200 символов), отражающее суть изменения.
4. Формат:
   ```markdown
   ## DD.MM.YYYY
   - Короткое описание изменения
   ```

## Общие сведения о проекте

- **PIXEL BATTLE** — многопользовательский pixel-art проект («место»), вдохновлённый r/place.
- Клиент: React 18 + TypeScript + SCSS Modules + Parcel 2.
- Сервер: Node.js + TypeScript (ts-node, pm2), WebSocket (`ws`), `node-canvas`, sqlite3.
- Авторизация: OAuth2 (Twitch, Discord, Steam, Telegram, VK).
- Подробная документация — в `README.md`.
